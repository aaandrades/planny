# Planny trip format (v1)

A trip is **one JSON object**. It's meant to be generated by an AI agent and pasted into Planny via **＋ New trip**.

## What to give the agent

| File | Use it for |
| ---- | ---------- |
| [`docs/trip.schema.json`](trip.schema.json) | **The contract.** Formal JSON Schema (draft-07) with a description on every field. Agents that support structured output can use it directly. |
| [`src/lib/aiPrompt.ts`](../src/lib/aiPrompt.ts) | The instructions and quality bar, i.e. what a *good* plan looks like. In the app, **New trip → Copy prompt** copies it. |
| [`public/sample-trip.json`](../public/sample-trip.json) | A complete 3-day example to imitate. |

A brief that works well:

> Using the Planny schema (`trip.schema.json`) and the instructions below, plan our trip. Output only the JSON.
> *(paste the prompt)* … MY TRIP: 10 days in May 2027, Lisbon → Porto → Douro Valley → Salamanca → Madrid, two adults, love food, wine and viewpoints, max 4h driving/day, mid-range budget around €3,000. Already booked: Hotel Avenida Palace in Lisbon for May 3–5 (conf. AB123).

To edit an existing trip, open it, go to **⋯ → Update plan → Copy JSON**, give the JSON to the agent with your changes ("swap day 4 and 5, add a winery"), and paste the result back. Anything you've already ticked stays ticked.

## Structure

```
Trip
├── title, subtitle?, emoji?, coverImage?, summary?, tags[]
├── startDate, endDate                 "YYYY-MM-DD"
├── travelers[], currency ("USD"), budget? { total }
├── days[]                             one per calendar day, in order
│   ├── date, title, summary?
│   ├── from?, to?, distanceKm?, driveHours?, image?
│   ├── stops[]                        in the order they happen
│   │   ├── title, type, time? "HH:MM"
│   │   ├── whyVisit?    → why it's worth stopping (one sentence, shown on the card)
│   │   ├── about?       → what the place IS: context, history, what's unique
│   │   ├── description? → what WE will do there
│   │   ├── highlights?  → 2–5 things not to miss
│   │   ├── tips?, openingHours?, bookingRequired?, bookingRef?
│   │   ├── durationMin?, cost?, url?, image?, optional?
│   │   └── location? { lat, lng, address? }
│   └── stay? { name, kind?, about?, address?, location?, checkIn?, checkOut?,
│               confirmation?, phone?, url?, cost?, notes? }
├── checklist[] { text, category? }
├── contacts[]  { name, phone?, note? }
├── links[]     { label, url }
└── notes?
```

**Stop `type`:** `drive` `food` `coffee` `sight` `activity` `nature` `beach` `shopping` `fuel` `rest` `photo` `stay` `other`
**Stay `kind`:** `hotel` `motel` `apartment` `house` `hostel` `camping` `cabin` `other`

## How each field shows up in the app

| Field | Where you see it |
| ----- | ---------------- |
| `whyVisit` | Bold line with a ♥ right under the stop name |
| `about`, `highlights`, `openingHours` | Expandable "About this place" section on the stop |
| `tips` | Yellow 💡 callout |
| `bookingRequired` | "Book ahead" label (hidden once `bookingRef` is set) |
| `location` | Map pin, the **Navigate** button, and the day's **Open route** in Google Maps |
| `cost` (stops and stays) | Day total and the budget breakdown in **Info** |
| `distanceKm`, `driveHours` | Day header and the trip stats |

## Rules the app enforces

- `title`, `startDate`, `endDate` and at least one day are required. Each day needs a `date` and a `title`, and each stop needs a `title`.
- Dates must be `YYYY-MM-DD`, times `HH:MM`, and `endDate` can't be before `startDate`.
- An unknown stop `type` becomes `other` instead of failing.
- Don't include `id`, `done` or `doneBy`. The app adds and manages them.

After changing [`shared/trip.ts`](../shared/trip.ts), run `npm run schema` to regenerate `trip.schema.json`.
